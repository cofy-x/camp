# Platinum visual and interaction design

Camp uses compact gray controls, crisp bevels, striped active title bars, shared icons and overlapping windows, initially informed by [Platinum9](https://github.com/grassmunk/Platinum9). Readability, Unicode and usable keyboard/touch behavior guide adaptations. Change shared controls and tokens together when the visual direction evolves.

Exact dimensions, colors, breakpoints and interaction values live in code:

Use shared controls and generic icons. Put feature-specific styling with its feature; shared primitives belong in Platinum with a Gallery example. Chicago Kare labels chrome, Inter labels body text, fields and documents. Keep Unicode fallbacks; avoid synthetic bold, forced bitmap text or shrinking text to conceal overflow. Gray raised/inset surfaces establish hierarchy; selection, focus and status use meaningful color plus a visible non-color cue.

Workflow changes preserve this visual system: compact controls, established typography and spacing, existing icons and window chrome. Persistent toggle buttons use the shared pressed state; a selected Room view remains identifiable during nested execution recovery. Product labels and demonstration content are English; user-authored and external content retain their original language.

## Content and information hierarchy

Lead with current facts and the next useful action. Use grouping, alignment and spacing to make relationships and actions clear. Add secondary labels and descriptions only when they provide information needed to choose, act or recover. Each sentence should support a decision, input or recovery step. When removing copy, first remove repetitions of headings, values and controls; do not replace them with another explanatory paragraph. Keep routine setup instructions and technical procedures in Diagnostics or the owning guide, while errors and consequential choices remain at their controls.

| Information | Placement |
| --- | --- |
| Current value, destination, recipients or work state | Beside its control/item |
| Required input, blocking capability, error and recovery | At the affected action/field |
| Shared publication, revocation or other decision-changing consequence | At the action or confirmation |
| Source explaining an externally locked field | Short label beside that field |
| Runtime provenance, detailed limits and previous observations | Named disclosure near the group |
| Repeated heading, action label or already visible status | Remove |

Keep labels concrete and vocabulary consistent. Empty states offer visible, editable starting points and enough explanation to choose; populated panels should not retain that tutorial. Tooltips supplement labels, never carry a required permission, consequence or recovery. Blocking errors remain outside disclosures.

Keep empty states compact and align their icons, text and actions as one group. Keep a command in its existing toolbar when that toolbar remains visible; do not repeat it in the empty pane. Use a quiet status row for unavailable optional Agent work, with one relevant setup destination. Room discussion remains usable without expanding a warning or reading setup instructions.

Distinguish configured from verified, private draft from shared version, captured from published, checks from tool activity, and completed work from human approval. A request allowance is not a billing cap. Simplification must preserve these facts and the user's unsaved input. Technical names belong in diagnostics when they do not help a product decision.

An ellipsis means further input/confirmation is required. **Ask agent…** prepares a cited draft requiring recipient selection and Send. Overflow menus use a concise accessible name, visible focus, ArrowDown opening and Escape focus return.

## Windows, controls and narrow layouts

Use one title frame, optional compact toolbar, remaining content area and optional status bar. The frame names the current location or selected object and its application; nested Workspace views also retain their Room context. When editing, creation or import owns the window, name that workflow in the frame and restore the location on return. Reusable forms keep a local workflow heading when an enclosing frame does not already identify it. Toolbars hold commands, filters and necessary navigation controls without repeating that name or its decorative icon. Keep the subject of a task, review or document in its content when it differs from the location, and show it once across its detail views. Interactive selectors and selected navigation entries remain available even when they repeat the frame's location. Status wraps without clipping save errors. Active/inactive, pressed, selected, focused, default, disabled and error states have distinct shared cues.

The menu bar follows the active window. File owns generic desktop selection/open commands and names the selected app; Window/overview recover hidden windows. Dialogs contain focus and restore it on dismissal. Shared nonmodal Palettes keep anchoring and dismissal with the host: Escape/close restores toggle focus; outside dismissal preserves the destination's focus. The persistent Needs me toggle shows unresolved responsibilities, with a separate quiet indicator for unread Activity. Its Inbox Palette opens Needs me first; Activity retains the notification feed and marks a notification read only after draft-safe navigation succeeds. Reading never resolves a business item.

Inbox keeps its outer frame and one tab content boundary. Tabs and the Work shortcut remain reachable while one content area scrolls. Both views use compact body-font titles and summaries; Activity combines Room and time on one metadata row, retaining the full timestamp. Needs me and Activity share the same contrasting highlight for pointer hover and keyboard focus, including metadata. Keep unread and keyboard focus cues visible.

Activity loads independently of team metadata. An unknown initial read shows loading; a failed read keeps accepted rows with its own retry, and revoked access clears them. Neither state becomes an empty feed or changes Needs me responsibility.

Visible readers share accepted data and in-flight requests. Unrelated notifications do not restart them, and a slow read completes before a needed follow-up. Folding a window pauses its reads while preserving its drafts, selection and reading position. Reopening revalidates the retained view. Optional application code loads inside its existing window; a failed download offers a local retry without reloading the desktop.

Preserve text selection, copy/paste, editing shortcuts and IME composition. Shading/hiding retains drafts and live work. Use the shared menu, Select, tabs, Radio and Progress rather than imitating them with feature-specific markup. Native wheel/touch scrolling remains usable even where host scrollbar artwork differs. Menus and dialogs stay inside visible bounds.

Adapt to application-window width through wrapping, stacking and scrolling. Narrow Settings/Agents/Runners replace sidebars with the shared pop-up. Narrow Workspace uses one Room identity/switcher with unread indicators and a separate action row. Long paths/titles wrap without widening the window. Narrow desktop mode keeps active-app identity and access to inactive windows.

Mouse and touch use the same compact visual control dimensions. Control Strip transparent hit regions may expand independently; they must not cover a window. Keep safe-area handling, close/return/save actions and keyboard focus reachable. Radio arrow keys move and select within the same native group, wrapping at both ends and skipping unavailable choices; Tab leaves the group. Avoid page-wide horizontal overflow. Wide document tables may have their own labelled, keyboard-accessible horizontal scroll region.

## Conversation and results

Use the [bundled pixel avatars](../apps/server/internal/avatars/catalog.json) consistently in conversations, mentions, member lists and Agent views. Members use animal silhouettes and Agents use machine silhouettes; visible names and accessible Agent identity remain present. Keep avatars visible in narrow conversations. The catalog's original artwork shares Camp's MIT license, loads from the Server and needs no external avatar service. Catalog IDs and their artwork are permanent; add an ID for a new design. Current profiles supply the conversation avatar without rewriting historical attribution or frozen execution inputs. Avatar choices use the shared Radio control with a visible selection and focus outline.

The composer names selected plus mentioned Agents once. **Post only** uses a discussion placeholder and keeps its no-execution consequence visible. Empty-Room starters prepare editable drafts, preserve existing text and never send. Upload, recipient and preview lists scroll within bounds so message input and Send remain visible in short windows. Preview buttons inside forms cannot submit them.

Upload completion belongs to its original Room/Thread and never sends automatically. Render Markdown directly and show readable UTF-8 files as source text. Other attachments offer the original download. File references identify the selected immutable version; they do not create a second parsed document or location scheme.

Completed results lead with publication/capture/check facts, then exact-version files, then output. Errors remain visible. Deletion-only results retain changes and patch access. A file list does not prove successful capture; interrupted or partial check evidence cannot show Passed or remain Running after termination. Conversation and inspector use the same record interpretation.

System records and verified Work session origins use compact event rows with a small review, collaboration or information glyph, attributed text, time and a primary destination. Identify a Work origin through its exact task/message relationship, never repeated text. Keep every distinct execution and its original message, author identity and source anchor. Missing historical author snapshots use a neutral Work label; current profiles do not supply historical names. Other member and Agent messages retain their identity avatars. Event overflow holds cited follow-up, thread navigation and explicit access to referenced files. Keep exact historical file versions accessible after shared files or review state advance, and preserve draft text and keyboard focus. New self-review events name that fact using user identity rather than display-name equality; existing audit text remains unchanged.

Discussion messages load independently of Room members and execution metadata. Open a bounded recent window, with Earlier/Later navigation and a Latest action when reading history. Direct references seek to their exact message without traversing intervening pages. Keep one message window mounted; preserve its reading anchor by message identity, pending draft and expanded-reply preference. Only a validated latest main conversation can advance its accepted read frontier; older windows and failed reads cannot. Failed background reads retain matching accepted messages and drafts with a visible retry; superseded Room/Thread reads cannot replace the newer selection. Room execution metadata is a bounded batch for the visible messages, without output, file contents or frozen input excerpts. Task history loads only when opened; unresolved Task attention is filtered before paging. Keep all historical thread states accessible; fetch complete records only for Details or an explicit cited handoff. Until Room routing is known, preserve the draft and require an explicit Post only choice or the original frozen retry intent before sending.

Short replies stay inline; long replies disclose the full original Markdown and citations. Keep Markdown controls mounted across desktop updates so focus, text selection and an in-progress pointer click survive. The first paragraph can be an earlier intention, so do not synthesize a conclusion from it. Remember expansion per message/account browser session; collapse restores focus. Follow-up references retain the complete message. Reading, previewing and downloading start no work and do not steal later reading position. Ask agent preserves Room versus existing Thread scope; Reply in thread explicitly creates that scope.

Typing belongs to the composer and empty-Room starters, without re-rendering populated history for each draft change. Reuse parsed Markdown when content is unchanged. Long replies parse when first opened and retain their mounted reading controls afterward. Execution details start from a small status projection and an exact reply lookup. Read raw files, checks and frozen requests only when their view opens; activity reads belong to Activity. These reads have independent errors/retries and cannot block current status. Diagnostics explicitly fetch their complete output and log pages; only a terminal snapshot obtained before the log traversal can certify complete activity.

## Library and human review

Library is the sole browser/editor. The window title shows the current location followed by Library; keep its toolbar for Sources and file commands without repeating the location. A mutable Resource named exactly after a linked Room plus ` files` uses that Room's name in the title; custom names and originals retain the exact Resource name. Sources retains every full Resource name. Group Resource commands separately from file commands and message handoff. New Document/History stay visible; More contains Refresh and administrator Environment. An empty file pane uses a compact, centered icon and status; creation stays in the toolbar without repeated instructions or actions. Sources uses a scrolling inset directory and a separate settings footer. On narrow windows it becomes a drawer; its toggle combines the Sources label with a sidebar glyph and the shared pressed state. Opening focuses selection, Escape/Done returns toggle focus and Tab exit preserves the intended focus destination. Apply navigation independently of list loading; a delayed initial read or retry cannot close a drawer or reset a newer interaction. Preview/Reviews tabs retain reading state. Give normal documents one vertical reading scroll owner; short windows can scroll the whole file pane to retain actions.

Safe Markdown supports GFM tables and read-only task checkboxes. Keep raw HTML disabled and remote images as explicit links. Preview commands place source/reference actions on the left and a compact Download control on the right. The download retains its native link, exact-version URL, filename and accessible identity without repeating the filename visually. More offers Download Files for the whole accepted Resource revision as a ZIP; the open menu retains that revision after newer publication. Keep it unavailable during an unaccepted read, private editing or another workflow rather than implying that private edits are included. Body headings keep the document font, distinct from chrome. A background read keeps the last error and its retry control available until a confirmed successful response replaces it; selecting another Resource or version clears errors belonging to the previous selection.

File lists and previews do not wait for version history. Load history only when opened, with scoped loading and recovery. Preview reads stop at the text-edit limit plus one boundary byte, retain a bounded visible prefix and keep the full original download. Editing requires complete, valid UTF-8 within the edit limit; a shortened prefix cannot establish editability or a save.

Environment settings lead with check names and read-only command summaries. Edit opens executable and literal argument fields or a package script inline; new checks open for input. Done validates fields before collapsing and keeps local edits until Save. Invalid fields open for correction during form validation. Remove check belongs in its heading; argument removal uses a compact minus beside its value and retains a useful keyboard focus destination. Arguments stay in one column, with Add argument below, and retain their exact values without shell parsing. Keep the optional relative working directory collapsed, showing configured paths in the row. Normal editing uses a compact change/save status beside Save; opening an unchanged form does not establish a save. Saved configuration appears when needed for conflict or unconfirmed-save recovery. Preserve local entries while newer settings arrive. Conflicts show the current saved configuration and offer Keep My Edits or Reload Saved Settings; keeping edits changes the editing baseline but never submits a save. Save uses the observed configuration revision. A lost response triggers readback rather than another write, and failed verification keeps the pending form until Check Saved Settings succeeds. Delayed observations or save responses cannot replace a newer revision or mark newer edits saved. Configuration actions start no Agent work.

Editor autosave is private. Explicit publication uses its frozen baseline; delayed responses cannot mark newer text published. Navigation, close and sign-out flush drafts; failure preserves local recovery. Private conflicts compare drafts before replacement; shared conflicts show latest bytes before explicit baseline change. History covers the complete shared file tree of a Resource. Its toolbar provides one Back to Files command through the existing draft-safe navigation owner. Keep a gap between the history heading and list. Each version leads with its change, current marker and author/time; show View Version and place comparison, conversation, version details and restoration under More. Routine not-run/not-configured checks remain in details; passed and unrecognized states remain visible. History opens exact old versions without restoring; a historical banner offers Return to Latest. Restore confirmation names all shared files in that source and creates another shared version while retaining existing history. Technical patch export belongs in comparison details.

After a confirmed publication, disable Publish Changes while both the content and baseline remain identical. New typing or a different baseline restores the action; uncertain publication and private-draft recovery retain their own controls.

Review forms freeze their file while open and survive background refresh. The request workflow is named once in its window frame, with the pinned filename in the form. Review lists show only their current Room or Resource while a different scope loads; a failed refresh retains that scope's last accepted rows and local retry. Uncertain requests and decisions keep the exact body and offer receipt recovery before edits, including after a newer or terminal status arrives. A definite protocol rejection restores editing while preserving the comment. Comments autosave privately and stay recoverable after another session decides. Keep the exact submitted document beside decision controls in wide windows. Narrow windows place the current decision before the document, with Open Document retaining its exact version. Requester management belongs under Manage Review. Keep status and document-version facts in their existing heading and preview rather than repeating explanatory paragraphs. Navigation waits for an in-flight review decision and its private receipt cleanup; a failed final draft write still blocks leaving, and a newer navigation choice supersedes an earlier wait. A committed user decision focuses its resulting state; background updates preserve position/focus. Resolved feedback and decisions remain in history. Delivered work leads with its immutable document; an outdated review separately offers current files. Ask agent prepares a cited draft and never starts work by itself. Formal approval/delivery always remains a human action.

## Readiness and Runners

An empty Room with unavailable execution gives administrators **Set Up Agent Work…**; ordinary teammates retain the browser discussion path. Getting Ready leads with one next action: configure a model, connect a supported Mac or Linux Runner, choose a Runner for an explicitly requested sample task, or start working after recorded success. Navigation starts no model request or enrollment. Connection navigation opens the existing persistent Connect Runner view; returning to machine overview keeps its unfinished connection draft. Detailed observations remain independently visible and never become a substitute for first-task evidence.

Getting Ready separates model configuration, observed provider responses, Runner self-test reports and recorded native task success. Opening and Refresh Status read the current aggregate without probing dependencies, invoking a model or pausing admission. Preserve the actual observation timestamps; prior observations survive failures and older responses cannot replace newer reports. Model, environment and storage panels load independently. An available runtime or previous connection cannot certify a current successful task. See [readiness ownership](architecture.md#readiness-reporting).

Models keeps optional reasoning effort beside request limits, with Provider default retaining the existing behavior. Saving settings starts no work and does not reinterpret admitted executions. Continuation keeps its original model configuration unless Use current model settings is explicitly selected; show the effect on new work beside that choice while retaining earlier execution records and request accounting.

Runners uses a selected-machine list/detail panel: Overview for availability and repair, Access for defaults/grants, Diagnostics for versions/timestamps/history. Agent choice stays in conversation; machine choice stays in Agents/Runners. A submitted request keeps its Runner and explains offline/busy waits. Storage advisories in Overview show the warning and retained/free values. Keep policy thresholds, observation timestamps and host commands in Diagnostics; an earlier or incomplete observation remains labelled in Overview. Storage advisories do not change execution readiness.

Connect Runner is a separate persistent view: download, private code, setup and first task. Show installer plus runtime transfer and an offline option. Preserve unfinished input and explain expiry/recovery. First-task success needs actual native work, separately from registration, connectivity and installation self-test. Destructive machine actions confirm their consequences.

First-task recovery belongs to the account and Runner. Retain the exact submitted body and request ID after an uncertain response. Leaving its view prevents later preparation stages or delayed navigation without discarding committed results. A confirmed admitted task opens its saved Run; a new sample requires explicit action after confirmed rejection or an observed terminal Run. Preserve the earlier receipt when starting another sample. Platform choices come from the Server catalog and remain explicit; the browser's platform does not identify the Runner host.

Collaboration start shows goal, participants, first Agent, finite allowance and unpublished draft before submission. Task detail leads with recorded state and version-specific files. Its goal starts as a compact heading; offer the full goal only when its text overflows, preserving that reading choice across tabs. Overview, Activity and Task setup separate result, turns and authorization; questions/errors/continuation stay visible outside tabs. Activity reads bounded input and turn pages. Live updates retain the current frozen input range, navigation anchors, unfinished text and uncertain write identity. New inputs are opened explicitly; history read failures retry the same range. Late inputs apply to the next round. Work completed does not establish approval/delivery.

Room navigation leads with Discussion, Work and Files. Work opens the existing Work application with the Room filter selected; Files opens the existing Library. Each application keeps one mounted detail/editor owner rather than a second Room-local copy. More holds Room management, shared notes, source rules and execution history. Finite tasks remain execution records inside a matter; earlier independent tasks remain reachable through history. Message follow-up retains the original as evidence. Remember this prepares an explicit shared-note edit with source provenance.

A matter's Overview leads with its goal, current question or progress, and result. Keep the goal visibly distinct from body text without increasing its size. Do not repeat a judgment status when the visible question already establishes the next action. A completed matter without visible progress or a result shows its recorded completion and any user-authored completion comment; do not invent an output or leave an empty panel. Activity shows one selected record category as a paged list; Manage shows one selected setting or action. Use shared tabs and selection controls instead of nested disclosure trees. Switching these views preserves private answers, request recovery and current authorization errors. Routine bookkeeping must not add a human confirmation to work already authorized to proceed.

Work has a desktop icon and one window for matters across Rooms. Its compact toolbar offers View and Room filters, Refresh and New work. My work defaults to the authenticated person's unfinished matters, with actionable questions and recovery needs first. Needs me aggregates their current judgments, reviews and exceptions from one Server-owned attention projection; normal waiting, running and historical failures remain quiet. It shares the global first page and unresolved count with the Inbox Palette, while Work owns Room filtering and further pages. Rows show the actual title, required step and necessary Room/type context, and open the existing matter, review or recovery owner. No queue action starts execution, approves or dismisses work. Completed shows their completed/cancelled matters, and All work includes team-visible matters. Room shortcuts select All work with that Room. Reading and notification unread state do not change business responsibility. Failed reads retain matching accepted rows with a visible retry; revoked access clears them, and an unknown count never appears as zero.

Matter facts, questions and existing authorized decisions load independently of Room configuration. Missing or failed settings cannot hide them. New execution, policy changes and allowance edits require matching accepted Room members and policies; pending context never substitutes empty permission or Agent defaults. Context retry preserves the matter's draft and revision/receipt guards.

An explicit Inbox or matter navigation opens Overview, including when the same matter is already visible. Background updates and Refresh retain the selected view. Changing the visible view preserves mounted draft and history owners. Work uses the selected matter's Room for members, defaults, rules and readiness; obsolete reads cannot install another Room's context. Creation requires a Room, inferred from an explicit Room/source shortcut when present. Changing the creation Room or leaving an editor flushes its private draft first. Successful creation clears the matching private draft before opening the recorded matter. If that cleanup fails, distinguish the saved matter from an uncertain submission and retain recovery for the same request; choosing another saved draft preserves it. Finite task and Run inspection stay in the same Work window with a return to the originating matter; inspecting records preserves mounted drafts. Open Room returns to the conversation.

Active matters offer View progress beside the current state, opening the existing Run inspector with a direct return to that matter. List rows and detail use the same current Task status when its identity matches the matter's active Task; paused work cannot appear Working. Historical failures/questions do not replace current progress, and completed, cancelled or stopping matter states take precedence. Explicit collaboration inspection retains its own return path. These read-only destinations share the existing draft-safe navigation owner and task/Room ownership checks.

Work creation groups Back to Work and the Room selector in one toolbar. Before execution, show the selected Agents, file access, finite turn/request allowance and team-visible draft scope in a compact summary. Editing controls may expand; those authorization facts remain visible. Start work and Keep track retain their distinct execution and recording intents.

Source management owns policies, setup and private comment credentials. Activity starts with recent events, an actual source filter and recorded outcomes; technical identifiers and original payload access belong in details. Failed history reads retain a route back to the previous page. Policy controls present Off, Observe and Auto as one choice with explicit saving. Selected people and Agents and the finite allowance stay visible; expand their editing controls when needed. Switching management views keeps drafts, pending request identities and the current activity range. A blocked background draft cannot prevent returning to its recovery view; changing source or leaving still flushes drafts before unmounting. Unsent credential edits require saving or explicitly clearing before leaving; tokens never enter browser storage. Late source lookups and draft flushes cannot override a newer navigation choice. While a transition saves drafts, a newer Workspace action cancels that transition and preserves the mounted draft. Feishu setup is deferred from the ordinary interface.

GitHub comments show recorded delivery state separately from permission to send again. Withdrawn comments offer no retry or resend. An unknown earlier send remains visible after withdrawal and can still be checked without sending another comment. Sending attempts and confirmed comment links belong in Delivery details, with explicit scan limits and missing legacy timestamps; an attempt alone does not establish delivery.

Matters lead with their goal and current question, progress or result. Show the action appropriate to that state rather than a generic state-machine command selector. Starting work confirms the actual participants and finite grant; budget editing, policy selection and technical identities stay in disclosures. A goal without completion criteria closes only with human confirmation. Business due dates and authorization expiry have different labels and effects. Stopping remains visible until the executing task has stopped.

Result summaries and exact-version files appear in the matter itself. Task drafts are team-visible; Room publication, human approval and delivery remain separate facts. Inbox leads with the actual matter title and question or result, and linked task notifications open the same matter. Keep empty history sections collapsed and detailed policy rules, provenance and version identities in disclosures. One refresh updates the item and its history; failed history reads retain a local retry, and pagination retains its range until an explicit refresh. Keep automatic follow-up consequences and blocking errors beside their controls; do not repeat architectural rules throughout forms.

Collaboration details lead with the goal and a compact state row. Turn history uses flat navigation rows, retaining turn order, Runner attribution and deferred-check facts.

Paused collaborations with exhausted model request counters show the used/approved allowance and explicit recovery beside Continue. Keep original execution errors separate; a final allowed request still in progress does not show an exhaustion warning.

Saved files from a failed execution are distinct from an accepted task draft. When safely retained work from the current attempt is available, Continue offers it explicitly under Starting files, alongside the task draft and latest Room files. Keep partial-work/check consequences and Review Saved Files beside that choice. Selection never publishes files or acknowledges inputs; failed or uncertain submissions retain the exact selected attempt for recovery.

Blocked execution opens its existing recovery owner and returns to the originating matter. A newer navigation choice supersedes delayed draft saves at both the matter and Workspace boundaries. Failed private saves remain visible when management disclosures close, with a direct return to the affected editor. Changing Room or policy invalidates a previously displayed default grant until the matching read completes.

## Review checklist

Choose scenes affected by the change; shared desktop changes need broader coverage. Record viewport, browser, device scale, content, window bounds and interaction state for reproducible comparisons. UI pull requests embed before/after screenshots directly as GitHub image attachments so reviewers can see the comparison without downloading an archive. CI artifacts retain supporting traces and reports. Keep generated screenshots/reports ignored.

| Scene | Inspect |
| --- | --- |
| Overlapping windows and menus | Active/inactive frames, layering, icons, menu bar and Control Strip |
| Controls/dialog/Palette | Pressed, selected, focus/default/disabled states, keyboard opening and dismissal |
| Changed app | Normal, loading/empty, long names, failed/uncertain writes and recovery |
| Narrow/short/resized windows | Reachable composer/actions, bounded scroll, no page overflow, focus-safe navigation |
| DPR 1, fractional (e.g. 1.5), DPR 2 | Text, borders, title stripes, icons and Unicode fallbacks |

Typical review sizes are 1440 × 900 desktop and 390 × 844 touch; include smaller app bounds and zoom where relevant. Use actual keyboard, pointer and touch actions alongside screenshots: switch, resize/shade, open/dismiss, edit and recover. Compare copy as well as geometry, including a failed state when reducing detail. Use [contribution checks](../CONTRIBUTING.md#checks); visual fixtures, actual protocol tests, native isolation and real model runs establish different evidence.
