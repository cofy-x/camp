# GitHub observations

A Room can receive GitHub repository webhooks. By default, deliveries create immutable observations awaiting a teammate's decision. Reading, refreshing and configuring a source make no model request. A teammate can choose a goal and approved Room Agents in **Start collaboration…**, or an administrator can explicitly delegate future work through [Automation](#automated-work-and-replies). The [task authority and publication contract](architecture.md#collaboration-tasks) remains authoritative.

## Connect a repository

1. As an administrator, open the Room's **Automation → Settings → Sources**.
2. Add `owner/repository` and a random webhook secret of 32–256 bytes. Events and original payloads will be visible to every enabled team member, like the Room.
3. Open **Webhook setup** and copy the Payload URL into that repository's GitHub Webhooks settings. Select `application/json`, enter the same secret, retain SSL verification and subscribe to **Issues**, **Pull requests** and **Issue comments**.
4. Use an externally reachable HTTPS Camp origin. Loopback HTTP is supported only for local protocol checks; this feature does not create a tunnel or configure GitHub, DNS, certificates or background services.

Camp verifies `X-Hub-Signature-256` against the exact body using HMAC-SHA256 and a constant-time comparison, following [GitHub's signature contract](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries). This endpoint accepts no member Cookie, browser Origin or Authorization header. The ordinary team APIs retain session and Origin protection. The [API contract](api.md#github-observation) owns request and response details.

Sources are fixed to a Room and repository name. The first valid delivery pins the repository's numeric identity; later deliveries must match both. A rename, transfer or replacement needs a new explicitly configured source. Disable the old source to retain its events and decisions. The same address can then have a replacement source, including after repository deletion/recreation. Only one source for that Room/address can be enabled at a time; re-enabling an older source requires disabling its replacement first. Repository IDs distinguish their histories. A Room supports up to 32 retained sources.

Clearing **Enabled** stops new deliveries and confirmations, including pending events. It preserves observations, receipts and already authorized tasks; use a task's own cancellation controls to stop that work. Rotating a secret immediately rejects deliveries verified with the old credential, including an ingress request that raced the rotation. Update the repository's webhook secret separately.

## Decide an event

Open **Automation → Activity → GitHub inbox** for events awaiting manual confirmation. **All events** includes accepted, dismissed and ignored observations. Opening an event shows its subject, external actor, original text and next action. **Event details** holds transport metadata and the original JSON download. GitHub identities are never mapped to Camp members. Bot, unresolved/ghost and unsupported events remain recorded as ignored observations.

The supported candidate actions are:

| Event | Actions |
| --- | --- |
| `issues` | `opened`, `reopened`, `edited` |
| `pull_request` | `opened`, `reopened`, `edited`, `synchronize`, `ready_for_review`, `closed` |
| `issue_comment` | `created`, `edited`, including PR issue comments |

Other event/action combinations and connection pings are recorded as ignored. This implementation does not poll GitHub history or automatically recover missed deliveries. Inspect GitHub's delivery history and explicitly redeliver a missed delivery, as described in [GitHub's delivery guidance](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks). Webhook setup itself grants no GitHub API credential, repository checkout or external reply permission.

**Start collaboration…** prepares an editable goal. It starts nothing until the teammate selects participants and submits the existing finite task authorization. The complete normalized event is copied into the task's append-only input log in UTF-8 chunks, labelled as untrusted external context supplied by the confirming member. Chunk wrappers preserve the authored body's whitespace. The task freezes the accepted input frontier and records its source event ID. Source context uses input protocol 1 and summary responses so large originals remain page-readable. The original webhook bytes are retained independently, without backfilling older tasks or changing their request hashes.

Confirmation writes the event decision, task, inputs, first queued Run, admission journal and task receipt in one SQLite transaction. One event can have one final human decision. Concurrent confirmations cannot create a second task, and an exact request replay returns its original task even after the source, model or route changes. Dismissal records the member, time and required reason without starting work. Event text cannot select Agents, expand budgets or resume work.

## Delivery, recovery and private state

The Server acknowledges a webhook only after its observation and delivery receipt commit. The delivery GUID is unique within its source; changed content under the same GUID conflicts. Byte-identical redeliveries are also deduplicated when their GUID changes. Ordering uses committed local sequences, rather than external timestamps. Reads use bounded pages and a frozen event frontier; decision states on those immutable events remain current.

After an uncertain task start, retain its exact request body and ID and use **Retry Start**, or open the event's recorded collaboration. Configuration and dismissal retain a private per-user receipt. **Check Saved Operation** reads that receipt without sending another write. Browser recovery stores only the operation ID for source settings; it never stores a webhook secret. Clearing an unresolved configuration recovery does not cancel an in-flight write. Expected revisions, source uniqueness and immutable event decisions still protect subsequent writes.

Raw deliveries are limited to 1 MiB, candidate titles to 1024 UTF-8 bytes and bodies to 64 KiB. Oversized/malformed deliveries fail explicitly; originals are never silently truncated. Credentials live in owner-only immutable files under `configuration/github-webhooks` in Server's data directory. SQLite stores opaque references and request hashes, never secret text. A file persisted before a failed database write can remain unreferenced; it cannot activate a source and is not automatically purged. Back up the complete stopped Server directory as described in [installation](install.md#data-upgrades-and-backup).

## Automated work and replies

The Room's **Automation** panel opens on **Activity**, with recent events first. Source filtering applies before pagination; older pages keep their original intake frontier until **Refresh Events** opens the latest range. Each row leads with its source, author, text preview and recorded outcome. **Details → Assessment decision** retains the frozen rules, proposed goal, reason and related tasks; **Event data** holds technical identifiers and the original payload download.

Open **Settings** and select the GitHub source to configure its policy. New policies are **Off**. Choose **Observe** or **Auto**, rules, allowed numeric GitHub actor IDs, approved Room Agents and finite task/daily allowances, then explicitly save. Participant selection expands when needed; a single participant is automatically first. The allowance summary stays visible while its numeric controls are under **Adjust allowance**. **Observe** assesses new eligible events using a model and records its result without starting work. **Auto** authorizes new finite collaborations under that delegation. Saving or reading settings makes no model request; enabling a policy applies only to future intake, never earlier observations. Each edit has a revision and new intake frontier. The [automation API](api.md#event-automation) owns limits and [bounded assessment](dsh.md#event-assessment) owns model behavior.

The same source Thread can supply context to several active tasks. Expand an event in **Automation**, choose **Follow in Collaboration…** and select an active task you manage. This starts no work. **Task setup → Conversation tracking** shows and controls existing subscriptions. New discussion is context under the existing grant; it does not resume finished work, increase allowances or implicitly answer a question. Room **Post only** also bypasses automatic work and subscription delivery. External actor attribution remains separate from Camp users. Existing explicit Agent requests keep their ordinary Run behavior.

Enable **Allow answers to task questions** only when listed GitHub participants may answer a task's current question. The exact command is `/camp answer <questionId> <answer>`, posted in its followed conversation by an allowed human actor. A matching unanswered question can continue within the task's remaining allowance. Stale, ambiguous and invalid commands start nothing. Ordinary comments supply context and are independently considered for new work.

To send ordinary issue/PR conversation comments, enable **Post task questions and results as GitHub comments**, save the policy and configure its separate **Comment credential**. Use a repository-restricted token and the numeric ID of its GitHub account. Credentials stay in owner-only Server files and never enter tools, task inputs, returned configuration, browser recovery or logs. This permission covers structured questions, actionable failures and final results; it grants no inline review replies, pull-request creation, pushes or merges.

Task setup shows each outgoing comment's frozen body, destination and delivery state. A lost POST response is **Delivery not confirmed**, followed by one read-only reconciliation. **Check GitHub Delivery** searches for the exact marker, body and recorded dispatch actors, including earlier accounts after credential rotation. Missing or incomplete evidence leaves delivery unknown. **Resend Comment…** explicitly permits another send and warns that a duplicate is possible; absence is never presented as proof of non-delivery. Known failed or blocked deliveries offer **Retry Comment** after repair. Obsolete questions and cancelled tasks withdraw queued sends and offer no resend; an earlier unknown outcome remains visible and can still be checked read-only. Withdrawn old questions stop blocking later task notices. **Delivery details** retains dispatch outcomes and confirmed comment links, with an explicit indication when a bounded scan may omit other matching comments. A delivery allows at most 32 dispatch attempts. Restart turns interrupted dispatch outcomes into unknown and reconciles without automatically posting again. Current source, task authority, comment permission and credential are rechecked before dispatch. Exact Camp output remains excluded from new automatic requests across sources observing the same repository discussion.

Policy drafts remain private and survive navigation. A newer saved revision offers **Keep My Edits** or **Reload Saved Policy**; keeping edits only changes the baseline and never saves automatically. Credential edits also retain their original policy revision until **Use Current Policy** explicitly accepts a newer baseline. Uncertain policy, credential, subscription and delivery commands retain their request ID for **Check Saved Operation**. If no receipt exists, **Cancel Unconfirmed Operation** either recovers a concurrently committed result or records a cancellation that rejects any late original write. Drafts stay intact; the UI never merely forgets the pending ID. Credential text stays only in the mounted form and is never stored in browser recovery. Save it or explicitly choose **Clear Credential Edits** before switching sources or leaving; uncertain submitted requests keep their separate receipt recovery. The [remaining event boundaries](architecture.md#current-implementation-limits) include missed-history polling and arbitrary external actions; [Feishu ingress](feishu.md) has its own authenticated adapter.
